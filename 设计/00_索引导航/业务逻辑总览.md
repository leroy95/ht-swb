# 业务逻辑总览

> 这一页用来回答：什么值得做、怎么推进、做到什么程度算通过。

## 1. 总原则
- 产品库回答“做什么”
- 计划库回答“怎么推”
- 执行手册回答“怎么落地”
- 所有文档都要回到“用户、价格、渠道、供应链、版本”五个判断点

## 2. 产品立项逻辑
1. 先看用户和场景
2. 再看价格带和差异化
3. 再看供应链能不能稳定做出来
4. 能做出来以后，先做 v1.0 验证
5. 有销量和反馈后再升级版本

### 2.1 产品分层
- 引流品：低客单、好理解、易传播
- 利润品：中高客单、稳定毛利
- 形象款：高辨识度、带品牌故事
- 定制款：按场景、合作或礼赠单独推进

## 3. 计划推进逻辑
1. 目标先行
2. 范围收窄
3. 只引用产品版本，不重复正文
4. 每个阶段都要有输出物
5. 通过样品、试销、反馈后再进入下一阶段
6. 不达标就回退、改版或暂停

### 3.1 阶段闸口
- 目标明确，才能进入推进
- 样品通过，才能进入试产
- 试产稳定，才能进入放量
- 放量后仍要复盘，决定是否合作扩展

## 4. 执行落地逻辑
- 先确认边界：授权、素材、工厂、交期、成本
- 先做样品，再做试产，再做大货
- 先低风险件，再高客单件
- 先验证品控，再验证销售
- 出现风险时优先停批次、留证据、再修正

### 4.1 常见异常处理
- 授权风险：改文案、改图稿、改品类
- 打样失败：换工厂或回到设计稿
- 良率不稳：先停线，改工艺参数
- 库存压力：减少 SKU，优先清热卖款

## 5. 索引使用规则
- 看到“是什么、卖给谁、版本演进”去产品库
- 看到“怎么推进、怎么分阶段”去计划库
- 看到“怎么做、怎么验收、怎么应对异常”去执行手册
